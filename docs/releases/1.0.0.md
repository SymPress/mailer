# 1.0.0

1.0.0 is the first stable release. It contains no code change compared to
0.7.1 and declares the public surface stable: hooks, the settings option and
its secret format, the console commands, the extension-point interfaces, the
value objects and the helpers extensions use. See
[Backward compatibility](../stability.md) and [Hooks](../hooks.md).

These notes summarise what changed since 0.1.9. The
[changelog](../../CHANGELOG.md) has the details for each release.

## Message Handling

- An invalid To, Cc, Bcc, Reply-To or forward address is skipped and the mail
  is sent to the remaining recipients, as in WordPress core. Each skipped
  address fires `sympress_mailer_recipient_skipped`.
- `Sender`, `Date` and `Return-Path` headers are applied as sender, date and
  return path instead of losing the mail; a configured return path still wins.
- Custom headers with a malformed name are skipped instead of aborting the
  mail, and all-digit header names no longer break delivery.

## Diagnostics

- `sympress_mailer_delivery_failed` fires when a mail cannot be delivered,
  with the log ID, the exception, the mail and the connection.
- A failed test email on the Tools screen shows the reason, with credentials
  replaced by `***`.
- A "Check Connection" button on the Tools screen connects and logs in to the
  SMTP server without sending mail.
- Tools > Site Health reports whether mail is delivered, without connecting to
  the mail server.

## Command Line

- `wp console mailer:test <to>` sends the test email and exits with `0`
  (accepted), `1` (failed) or `2` (invalid address).
- `wp console mailer:status [--probe]` shows the delivery configuration
  without secrets and exits with `1` when the settings cannot be read, fail
  validation or fail the connection check.

## Admin Screens

- Validation errors on save are shown in a notice on the same tab, and the
  form keeps the entered values except secrets.
- The General tab shows only the fields of the selected provider.
- The remaining admin texts are translatable.

## Multisite

- Uninstalling the plugin deletes each site option and each network option by
  its own "Delete Settings on Uninstall" flag.

## Upgrading

- No data migration and no settings change is needed. The option structure
  and the encrypted secret format are unchanged since 0.1.9.
- `symfony/console` is now a direct requirement. It is already installed
  through `sympress/kernel`.
- Extensions that require this package with a `^0.1` constraint must allow
  `^1.0`.

Behaviour changes an operator may notice:

- A mail with one invalid recipient is sent to the valid recipients instead of
  failing.
- A mail with a `Sender`, `Date` or `Return-Path` header is delivered.
- A settings save that fails validation shows a notice on the settings screen
  instead of an error page.
- On multisite, uninstalling deletes each site and network option by its own
  "Delete Settings on Uninstall" flag, so sites that opted in lose their
  settings and network settings follow the network's choice.
